# ADR-0004：重试与幂等策略

[English](0004-retry-and-idempotency.md) | [简体中文](0004-retry-and-idempotency.zh-CN.md)

- 状态：已接受
- 日期：2026-09-08

## 背景

仅凭 HTTP 状态码无法判断 OpenAI 请求是否可重试。429 临时限流与 429 额度或消费上限错误需要不同处理。SDK 和应用的嵌套重试会放大真实请求次数。没有稳定业务标识时重试副作用，可能重复执行操作。

## 决策

- 在调用重试策略前，将供应商错误映射为稳定的失败类型。
- 只重试显式瞬时失败，例如临时限流、服务过载或选定的传输超时。
- 不原样重试认证、无效请求、账单、余额、消费上限或用量上限错误。
- 将有效 `Retry-After` 视为最小等待时间，并增加注入的抖动。
- 没有有效服务端延迟时，使用带上限的指数退避和抖动。
- 同时限制总尝试次数和累计等待时间。
- 重试计算保持为纯逻辑；调度和睡眠由调用方负责。
- 禁用 SDK 重试，或将其纳入同一个全局预算。
- 对副作用幂等使用业务 `operationKey` 和请求指纹；`call_id` 只负责协议关联。
- 缓存成功的幂等结果，不永久缓存瞬时失败；同一操作键搭配不同指纹时拒绝执行。

## 影响

- 无需时钟和真实睡眠即可测试重试行为。
- 临时失败不会成为永久污染结果。
- 内存实现只能证明单进程语义。
- 生产写操作仍需要持久化存储、唯一约束，以及处理“外部提交完成但幂等记录尚未落库”窗口的事务策略。
