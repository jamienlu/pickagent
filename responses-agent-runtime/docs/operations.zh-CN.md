# 运维说明

[English](operations.md) | [简体中文](operations.zh-CN.md)

## 部署模型

CI 构建默认制品，进程启动时注入在线配置，每个请求创建一个隔离的 `OpenAiOnlineRunner` 会话。每个会话独占并关闭自己的 SDK 客户端。预发布与生产环境的凭据、模型、预算和消费上限必须分离。

## 生产必备控制

- API 密钥必须放在秘密管理系统中并定期轮换，禁止写入源码、镜像、日志或命令历史。
- 除本地调用数、工具数、时长、超时、重试和输出 Token 预算外，还要设置组织侧限流与消费上限。
- 敏感 `ToolHandler` 前必须增加授权和人工审批。
- 在宣称具备崩溃安全或分布式幂等前，用持久化事务存储替换 `InMemoryIdempotencyStore`。
- 按应用数据策略脱敏用户输入、模型输出、工具参数、工具结果、response ID 和 call ID。
- `live` 测试只能人工执行，或放在严格受控、使用小型已审批模型并设置费用上限的定时环境中。

## 可观察终态

每个正常 Runtime 终态都包含 `RunUsage(modelCalls, toolCalls, elapsed)`。

| 结果 | 运维含义 |
| --- | --- |
| `Completed` | 最终回答已接受。 |
| `Stopped` | 预算或本地安全边界阻止继续执行。 |
| `ModelFailed` | 供应商或 transport 失败已映射为稳定的 `FailureKind`。 |
| `ToolFailed` | 已批准的 handler 报告了预期执行失败。 |

按终态类型和 `FailureKind` 统计次数与延迟。认证失败、账单/额度失败、持续命中截止时间、持续限流和服务过载都应告警。不要把异常消息当作指标标签。

## 发布与回滚

1. 执行发布验收清单。
2. 使用独立凭据和保守预算部署到预发布环境。
3. 只执行已批准且可恢复的工具，检查终态分布与费用。
4. 以小比例进行生产灰度。
5. 认证、额度、错误率、延迟或工具安全指标超限时，回滚应用制品或禁用在线入口。

系统不会回滚在后续工具或模型失败前已经完成的外部副作用。业务需要补偿时，领域 handler 必须自行实现。

## 事故留证

记录制品版本、脱敏配置、终态类型、`FailureKind`、消耗快照、数据策略允许的供应商请求关联信息，以及工具副作用是否发生。绝不能记录 API 密钥或未脱敏的敏感载荷。
