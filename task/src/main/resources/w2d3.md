## 主动回忆题：

1. 为什么 `strict=true` 仍不能替代鉴权和业务审批？

   1. 只保证函数参数符合声明的 JSON Schema，例如字段齐全、类型正确、没有额外字段。它不判断

   2. 退款、删除等操作是否需要人工审批；

   3. 参数虽然合法，但业务上是否危险。

2. `function_call` 与 `function_call_output` 靠哪个字段关联？

   1. `call_id`

3. 为什么 model adapter 不应自行循环并执行工具？

因为 adapter 的职责应限制为供应商协议转换。Runtime/Application：

最大步骤数和停止条件；

工具权限与审批；

调用预算和审计；

失败分类；

是否继续下一轮；

工具结果如何加入上下文。

如果 adapter 自行循环，调用次数会被隐藏

4. 如果响应同时包含两个 function call，当前单调用核心应如何处理？

`AgentDecision.ToolCall` 只能无损表达一个调用。等业务真正需要多调用时，再显式升级核心 capability 和 Runtime 策略,应当失败关闭

5. reasoning 模型产生工具调用时，为什么不能只保存 `call_id`？

`call_id` 只解决“这个结果属于哪个调用”，不保存模型继续推理所需的上下文;reasoning item,function_call模型reason可能同时返回





## Responses function-call bridge


1. 协议格式校验、运行时参数校验、执行授权分别由谁负责

协议格式校验由 OpenAI adapter/mapper 负责，运行时参数校验由 `ToolRegistry` 负责，执行授权由应用层在调用 handler 前依据真实主体与资源策略负责。

2. 参数 JSON 解析成功”和“ToolRegistry 允许执行”为什么是两个阶段

JSON 解析成功只证明语法正确、根是 object 且当前值能收窄为字符串；Registry 允许执行还要求工具在 allowlist 中、字段集合与 `ToolDefinition` 完全一致且值不为空白。之后仍应经过独立的应用授权/业务审批

1. 五节点往返链路

   1. SDK function_call call_id / name / arguments 

   2. OpenAiFunctionCallMapper 

   3. core ToolCall

   4. ToolHandle

   5. OpenAiFunctionCallOutputMapper

a->b 解析arguments JSON

b -> c 校验工具名、精确字段、blank

c -> d 执行离线工具

d -> e sdk 输出

## time3

1. 多步循环：

官方五步是“带工具请求模型 → 收到调用 → 应用执行 → 带结果再次请求 → 最终回答或更多调用”；最后一步允许继续产生调用，所以停止策略属于 Runtime。

[Tool calling flow]([https://developers.openai.com/api/docs/guides/function-calling#the-tool-calling-flow](https://developers.openai.com/api/docs/guides/function-calling#the-tool-calling-flow))

2. 多个调用：响应可能包含零个、一个或多个调用。官方建议按多个处理；当前单调用核心选择 fail-fast，而不是只取第一个。

[Handling function calls]([https://developers.openai.com/api/docs/guides/function-calling#handling-function-calls](https://developers.openai.com/api/docs/guides/function-calling#handling-function-calls))

3. reasoning 续接：reasoning 模型随工具调用返回的 reasoning items 必须与 tool call outputs 一起传回。当前 mapper 允许它前置但不保存，因此今天的桥接并不是完整 adapter。

[Reasoning items]([https://developers.openai.com/api/docs/guides/function-calling#the-tool-calling-flow](https://developers.openai.com/api/docs/guides/function-calling#the-tool-calling-flow))
