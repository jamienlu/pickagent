## 主动回忆题

1. `attemptsMade=1` 和 `maxAttempts=3` 分别表示什么？

attemptsMade 表示已经发出的请求总数，并包含刚刚失败的这一次`attemptsMade=1`决策器是在决定是否安排第一次重试，maxAttempts=3 最多发出初始请求加两次重试。

2. 两个 HTTP 429 为什么可能需要完全不同的处置？

   1. `429 + error.code=slow_down` 是临时流量上升过快，可以在预算内退避重

   2. `429 + error.code=credit_balance_exhausted` 是预付额度耗尽，必须充值而不是重试。

3. `Retry-After=5s`、jitter=`250ms` 时，为何不能只等待 5 秒？

`Retry-After` 存在时至少等待该时长；缺失或无效时指数退避加 jitter，失败请求本身也消耗每分钟限额，不能紧密循环

4. `call_id` 为什么不能充当扣款操作的幂等键？

`call_id` 由模型供应商为工具调用生成扣款操作必须使用业务 `operationKey`、授权与持久化幂等保护

5. 缓存失败结果或允许同 key 不同请求会造成什么故障？

请求带上别的上下文，出现未知调用



## 离线责任链路：

`SDK call → mapper → core ToolCall → Registry → handler → ToolResult → output mapper → SDK output`


    A[SDK function_call fixture] -->|OpenAiFunctionCallMapper：解析协议 JSON| B[core ToolCall]

    B -->|ToolRegistry：白名单和参数校验| C[handler]

    C -->|IdempotentExecutor：业务 operationKey 防重| D[ToolResult]

    D -->|OpenAiFunctionCallOutputMapper：保留 call_id| E[SDK function_call_output]

    F[OpenAiFunctionToolMapper：生成 strict schema] -. 告知模型的契约 .-> A

    G[RetryPolicy：只决定停止或等待多久] -. typed decision .-> C


## 新增测试证明与证明边界


1. strict schema 被保留

   1. 正确：SDK 4.52.0 fixture 中 `strict=true`、object、properties、required、`additionalProperties=false` 的本地映射 

   2. 不正确：真实模型一定遵循 schema、所有模型/端点都支持该 schema

2. call_id 往返不变

   1. 正确：当前单调用链路没有改写关联标识

   2. 不正确：供应商会返回有效 call_id、多调用或 reasoning 上下文得到完整支持

3. Retry-After + jitte

   1. 正确：纯函数在固定输入下返回 `5.25s`，且既有测试覆盖总预算停止

   2. 不正确：真实服务器是否发送该 header、实际调度延迟和端到端延迟

4. 永久错误不重试

   1. 正确：provider-neutral 分类为认证错误后不会计算 jitter 或继续重试

   2. 不正确：adapter 对每种真实供应商错误都分类正确、账户/计费状态永久错误不重试

5. 同 key 同指纹

   1. 正确：单进程串行重放命中首次成功结果，handler 可再次进入但底层副作用一次

   2. 不正确：并发竞争、进程崩溃、跨进程一致性、数据库持久性或 exactly-once

6. 同 key 不同指纹

   1. 正确：本地执行器在第二次副作用前明确拒绝冲突

   2. 不正确：分布式节点同时首次写入时不会发生竞争

7. 失败不缓存

   1. 正确：抛异常后相同操作可再次执行并成功

   2. 不正确：异常发生在外部提交之后时不会重复副作用 

8. 多调用拒绝

   1. 正确：当前单调用 mapper fail-fast，不静默取第一个

   2. 不正确：并行调用、依赖排序或批量 tool outputs


## 官方正文检索记录

1. `function calling call_id strict multiple reasoning items`

   1. [https://developers.openai.com/api/docs/guides/function-calling](https://developers.openai.com/api/docs/guides/function-calling)

   2. `function_call_output.call_id` 必须关联原调用；strict mode 要求对象关闭额外属性且 properties 全部进入 required；模型可能一次返回多个调用；reasoning 模型的 reasoning items 必须随工具结果续接 

   3. `OpenAiFunctionToolMapper`、`OpenAiFunctionCallMapper`、`OpenAiFunctionCallOutputMapper`、`strictSchemaIsPreservedAtTheSdkBoundary`、`callIdSurvivesTheCompleteSdkCoreSdkRoundTrip`、`multipleFunctionCallsAreRejectedInsteadOfSilentlyTruncated`

2. `structured outputs JSON mode refusal incomplete`

   1. [https://developers.openai.com/api/docs/guides/structured-outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

   2. JSON mode 只保证合法 JSON，Structured Outputs 才保证受支持 schema 的 adherence；refusal 不一定符合业务 schema，incomplete 也不能进入成功解析

   3. `StructuredResponseHandler` / `StructuredOutputDecoder`；本日 strict schema 测试只证明本地映射，没有声称真实响应一定成功

3. `error codes 429 credit rate limit 503`

   1. [https://developers.openai.com/api/docs/guides/error-codes](https://developers.openai.com/api/docs/guides/error-codes)

   2. 同为 HTTP 429，临时限流和 `credit_balance_exhausted` 处置不同；认证、额度和非法请求不能靠原样重试修复

   3. `FailureKind`、`RetryPolicy`；`permanentFailureStopsWithoutConsultingJitter`

4. `rate limits Retry-After jitter total budget`

   1. [https://developers.openai.com/api/docs/guides/rate-limits](https://developers.openai.com/api/docs/guides/rate-limits)

   2. `Retry-After` 是最低等待，之后追加小 jitter；缺失时使用指数退避加 jitter；限制尝试次数和总时间，并考虑 SDK 已做的自动重试 

   3. `RetryPolicy`；`retryAfterIsTheMinimumAndReceivesInjectedJitter` 及既有预算测试
