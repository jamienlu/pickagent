# Responses 协议账本


## 检索：Responses reasoning items function call output preserve history

| 来源 | 官方正文结论 | 代码不变量 |
| --- | --- | --- |
| [Reasoning models—Keeping reasoning items in context](https://developers.openai.com/api/docs/guides/reasoning#keeping-reasoning-items-in-context) | reasoning 模型发生 function calling 时，应把伴随的 reasoning items 与工具输出一起续接；连续调用时保留最后一条 user 消息之后的 reasoning、call 和 call output。 | `prepare` 按原顺序验证并保留 reasoning/message/function_call，`append` 只追加匹配的 output。 |
| [Responses Java API—List input items](https://developers.openai.com/api/reference/java/resources/responses/subresources/input_items/methods/list) | reasoning 是可进入后续 Responses 输入的协议 item；手动管理上下文不能把它压缩成可见文本或只剩调用标识。 | 使用原 SDK 对象，不根据可见字段重建；对象身份、opaque content 和扩展字段得到保留。 |
| [Function calling—Handling function calls](https://developers.openai.com/api/docs/guides/function-calling#handling-function-calls) | 应先续接 `response.output`，再追加带原始 `call_id` 的 `function_call_output`；reasoning 模型的 reasoning items 也随工具结果返回。 | 完整第一轮协议必须在 handler 之前通过 `prepare`；结果只能追加到匹配 call。 |


## 协议顺序

    U[user] --> R[reasoning]

    R --> M[assistant/message 可选]

    M --> C[function_call]

    C --> O[function_call_output]

    O --> N[下一次模型调用]


第一份离线 fixture 为 `reasoning → function_call`。如果模型在调用前还返回 assistant/message，它也必须保持原位置。工具结果不是历史的替代品，而是追加的新协议 item。



## 至少三条不变量

1. 从上一响应复制到下一输入的协议项必须保持顺序，不能只提取最后一个 `function_call`。

2. reasoning、assistant/message 和 function_call 使用 SDK 原对象转换，不能重建后丢失 encrypted content、phase、status 或未知扩展字段。

3. `function_call_output.call_id` 必须精确等于目标 `function_call.call_id`，且只能追加在该调用之后。

4. 当前实现只支持串行单调用；零调用、多调用或未知 item 不做猜测，直接失败。

5. 返回值是不可变快照，调用方无法在校验后改变顺序或替换协议项。

6. 所有第一轮协议校验必须发生在 `ToolRegistry.execute` 之前；协议非法时 handler 执行次数为 0。

7. 第二轮只允许 reasoning 与 assistant/message；任何工具项或未知 item 都 fail-closed。


## 测试矩阵

正常路径 : reasoning/message/call 保持顺序与对象身份，匹配 output 追加在末尾 

零调用  : `NO_FUNCTION_CALL` 

多调用 :  `MULTIPLE_FUNCTION_CALLS`，不静默选择第一个 

call_id 错配 : `CALL_ID_MISMATCH`，不构造下一请求 

未知类型 : `UNKNOWN_OUTPUT_ITEM`，不静默丢弃 

不可变性 : 修改返回快照抛出 `UnsupportedOperationException`；源列表后续变化不影响快照 

副作用顺序 : 非法 `file_search_call + function_call` 在 `prepare` 阶段失败，handler 执行次数为 0

第二轮非允许项 : `UNEXPECTED_FINAL_OUTPUT_ITEM`，不能因同时存在文本而忽略工具项


## 完整离线回合

first fixture: reasoning + function_call

    → OpenAiResponseLedger.prepare（完整协议校验，无副作用）

    → OpenAiFunctionCallMapper（参数 JSON 映射，无副作用）

    → ToolRegistry（校验并执行一次）

    → ToolResult

    → OpenAiResponseLedger.append（call_id 校验；原历史 + function_call_output）

    → second replay fixture

    → final assistant text

    → STOP


协议风险：此前的核心 `ToolCall` 只能保存 `call_id/name/arguments`，若直接由它构造下一请求，会丢掉 reasoning item，模型下一轮缺少协议上下文。


测试遗漏：原有 W2 测试只验证 `call_id` 往返；第一版 W3D1 测试也只直接测试 ledger，未证明 Replay 在副作用前调用它。修改是增加“非法第一轮协议时 handler=0”和“第二轮未知工具项 fail-closed”两项回归测试。
