# Responses 协议账本


## 检索:Responses reasoning items function call output preserve history


1. [Reasoning models—Keeping reasoning items in context]([https://developers.openai.com/api/docs/guides/reasoning#keeping-reasoning-items-in-context](https://developers.openai.com/api/docs/guides/reasoning#keeping-reasoning-items-in-context)) 

2. reasoning 模型发生 function calling 时，应把该调用伴随的 reasoning items 与工具输出一起续接；连续调用时需要保留自最后一条 user 消息以来的 reasoning、call 和 call output。 

3. `OpenAiResponseLedger` 按原顺序保留 reasoning/message/function_call，并将 output 追加到末尾。 



1. [Reasoning models—manual context]([https://developers.openai.com/api/docs/guides/reasoning#keeping-reasoning-items-in-context](https://developers.openai.com/api/docs/guides/reasoning#keeping-reasoning-items-in-context)) 

2. 手动裁剪上下文时，从最后一条 user 消息到 function call output 之间的所有 item 都应原样传入下一请求。

3. 使用原 SDK 对象，不根据可见字段重新构建；对象身份、opaque content 和扩展字段得到保留。 



1. [Function calling—Handling function calls]([https://developers.openai.com/api/docs/guides/function-calling](https://developers.openai.com/api/docs/guides/function-calling)) 

2. 应先把 `response.output` 加入下一次输入，再追加带原始 `call_id` 的 `function_call_output`；reasoning 模型返回的 reasoning items 也必须续接。 

3. output 只能追加在匹配 call 之后；零调用、多调用、错配和未知 item 全部 fail-fast。 


## 协议顺序

    U[user] --> R[reasoning]

    R --> M[assistant/message 可选]

    M --> C[function_call]

    C --> O[function_call_output]

    O --> N[下一次模型调用]


第一份离线 fixture 为 `reasoning → function_call`。如果模型在调用前还返回 assistant/message，它也必须保持原位置。工具结果不是历史的替代品，而是追加的新协议 item。



## 至少三条不变量

1. 从上一响应复制到下一输入的协议项必须保持顺序，不能只提取最后一个 `function_call`。

2. reasoning、assistant/message 和 function_call 使用 SDK 原对象转换，不能重建后丢失 encrypted content、phase、status 或未知扩展字段。

3. `function_call_output.call_id` 必须精确等于目标 `function_call.call_id`，且只能追加在该调用之后。

4. 当前实现只支持串行单调用；零调用、多调用或未知 item 不做猜测，直接失败。

5. 返回值是不可变快照，调用方无法在校验后改变顺序或替换协议项。


## 测试矩阵

正常路径 : reasoning/message/call 保持顺序与对象身份，匹配 output 追加在末尾 

零调用  : `NO_FUNCTION_CALL` 

多调用 :  `MULTIPLE_FUNCTION_CALLS`，不静默选择第一个 

call_id 错配 : `CALL_ID_MISMATCH`，不构造下一请求 

未知类型 : `UNKNOWN_OUTPUT_ITEM`，不静默丢弃 

不可变性 : 修改返回快照抛出 `UnsupportedOperationException`；源列表后续变化不影响快照 


## 完整离线回合

first fixture: reasoning + function_call

    → OpenAiFunctionCallMapper

    → ToolRegistry（校验并执行一次）

    → ToolResult

    → OpenAiResponseLedger（原历史 + function_call_output）

    → second replay fixture

    → final assistant text

    → STOP


协议风险：此前的核心 `ToolCall` 只能保存 `call_id/name/arguments`，若直接由它构造下一请求，会丢掉 reasoning item，模型下一轮缺少协议上下文。


测试遗漏：原有 W2 测试只验证 `call_id` 往返，没有断言 reasoning 对象和顺序进入下一请求。修改是增加对象身份、顺序、未知类型、不可变快照和完整两轮 Replay 行为测试。
